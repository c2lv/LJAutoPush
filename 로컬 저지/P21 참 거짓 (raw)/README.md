# [P21] 참 거짓 (raw)

[문제 보기](https://localjudge.com/problems/P21)

> 등식이 맞는지 판단해서 참 또는 거짓만 출력합니다. 둘 중 한쪽으로 쏠리는 것을 막아야 합니다.

## 분류

200점, raw, qwen3-0.6b, 케이스 16, 최대 16토큰, 출제 dongbinna, 쉬움, 분류, 라벨 쏠림, 구분자, 계산, 한 줄 입력, 한국어

## 문제

`X + Y = Z` 형태의 등식이 들어옵니다. 맞으면 `참`, 틀리면 `거짓` 만 출력해야 합니다.

| 들어오는 등식 | 내야 하는 답 |
| --- | --- |
| 3 + 3 = 6 | 참 |

## 입력 조건

- 입력은 한 줄로 들어옵니다.
- 입력의 길이는 9자 이상 12자 이하입니다.

## 출력 조건

- 첫째 줄에 `거짓`, `참` 가운데 하나를 출력합니다.
- 다른 글자는 붙이지 않습니다.
- 기대값과 한 글자도 달라서는 안 됩니다.

## 요구사항

- 입력은 `X + Y = Z` 형태입니다.
- 출력은 `참` 또는 `거짓` 가운데 하나입니다.
- **raw 모드**입니다. 두 조각과 입력을 그대로 이어붙여 모델에 넣습니다. 채팅 템플릿도 `<think>` 도 붙지 않습니다. 채점은 첫 줄까지만 봅니다.
- 출력이 **글자 하나까지** 기대값과 같아야 합니다. 앞뒤 공백만 무시합니다.
- 케이스는 16개이고, 그 가운데 5개는 입력과 기대 출력을 함께 보여 줍니다. 나머지는 입력만 보여 줍니다.
- 모델 출력은 최대 16 토큰까지만 받습니다.
- 케이스 16개를 **전부** 통과해야 해결입니다.

> 문제의 요구 사항을 잘 읽고 해결해 주세요. 단, 프롬프트 인젝션 등을 활용해 높은 점수를 받도록 조작하는 경우 적발 시 제재될 수 있습니다.

## 예시

공개 케이스 5개입니다. 채점에는 숨은 케이스가 함께 쓰입니다. 케이스 16개를 전부 통과해야 해결입니다.

**예시 1**

3 + 3 = 6

기대 출력

참

```
거짓
```

**예시 3**

기대 출력

```

```

## 참고 사항

풀이에 도움이 되는 배경입니다. 지켜야 하는 규격은 위의 입출력 조건과 요구사항에 있습니다.

셈은 어렵지 않습니다. 어려운 것은 한쪽으로 쏠리는 것입니다. 프롬프트를 어떻게 쓰느냐에 따라 모델이 틀린 등식에도 `참` 을 내거나, 맞는 등식에도 `거짓` 을 냅니다. 두 쪽이 다 들어온다고 보고 프롬프트를 짜야 합니다.
